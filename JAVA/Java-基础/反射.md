## 什么是反射

### 一句话定义

**反射（Reflection）是 Java 提供的一种能力：在程序运行时，动态地获取类的信息并操作类（创建对象、调用方法、访问字段）。**

关键在于「**运行时**」和「**动态**」这两个词——它打破了「编译期确定一切」的限制。

### 为什么需要反射（理解的关键）

正常情况下，我们用对象是这样的：

```java
User user = new User();        // 编译期就知道要创建 User
user.setName("张三");           // 编译期就知道要调 setName
```

此时**类名、方法名在编译期就已确定**，编译器会做类型检查，.class 文件里直接引用这些符号。

但有些场景下，**编译期根本不知道要操作哪个类**：

```java
// 假设配置文件中写着 class=com.example.UserService
// 编译时不知道这个类是否存在，更不知道它有什么方法
String className = readConfig("class");
// 那么如何创建它的对象、调用它的方法？
```

反射就是解决这个问题的：**把「类」本身也当作一个对象来操作**。

### 核心：万物皆对象，类也是对象

Java 中有一句经典的话：**「反射就是把类也当作对象」**。

- 普通对象：`User` 的实例是一个对象，你可以调用它的方法。
- **类的对象**：每个类被 JVM 加载后，都会生成一个**唯一的 `Class` 对象**，它描述了这个类的一切——有哪些字段、哪些方法、哪些构造器、父类是谁、实现了哪些接口。

```java
Class<User> clazz = User.class;   // 这就是「User 这个类」对应的对象

clazz.getName();                  // 获取类名
clazz.getDeclaredFields();        // 获取所有字段
clazz.getDeclaredMethods();       // 获取所有方法
clazz.getDeclaredConstructors();  // 获取所有构造器
```

一旦拿到了 `Class` 对象，就等于拿到了这个类的「说明书」，后续就能据此创建实例、调用方法、读写字段。

### 编译期绑定 vs 运行期绑定

| 对比项 | 常规调用（静态绑定） | 反射调用（动态绑定） |
|:---|:---|:---|
| 类何时确定 | 编译期 | **运行时** |
| 类型检查 | 编译期，安全 | 运行时，可能抛异常 |
| 性能 | 快（可直接优化） | 慢（需动态解析） |
| 灵活性 | 低（改类名要改代码） | **高（可通过配置/字符串指定）** |
| 典型场景 | 业务代码 | 框架、工具类 |

**举例说明**：要把 `User` 改成 `Order`。

```java
// 常规调用：必须修改源码并重新编译
User obj = new User();

// 反射调用：改配置文件即可，代码不动
String className = config.get("targetClass");   // 从配置读取
Class<?> clazz = Class.forName(className);
Object obj = clazz.getDeclaredConstructor().newInstance();
```

**这正是框架的基石**——Spring 不知道你的业务类叫什么，但它能通过配置文件/注解扫描拿到类名，再用反射创建和管理你的对象。

### 获取 Class 对象的三种方式

```java
// 方式一：类名.class —— 最安全，编译期检查，性能最好
Class<User> c1 = User.class;

// 方式二：对象.getClass() —— 需要已有实例
User user = new User();
Class<?> c2 = user.getClass();

// 方式三：Class.forName("全限定名") —— 最灵活，可从字符串动态加载
Class<?> c3 = Class.forName("com.example.User");
```

| 方式 | 适用场景 | 特点 |
|:---|:---|:---|
| `类名.class` | 编译期已知类型 | 不触发类初始化，性能最优 |
| `对象.getClass()` | 已有对象实例 | 继承自 `Object` |
| `Class.forName()` | **编译期未知类型**（配置/字符串） | **会触发类初始化**，是反射动态性的核心 |

> **注意**：同一个类在 JVM 中**只有一个 `Class` 对象**，三种方式拿到的是同一个（`c1 == c2 == c3`）。

### Class 对象从哪来

- Java 源码编译后生成 `.class` 字节码文件，其中保存着类的全部结构信息。
- JVM 通过**类加载器（ClassLoader）** 把 `.class` 读入内存，并在方法区中创建对应的 `Class` 对象。
- 类通常是**第一次使用时才加载**（懒加载），这为「运行时动态加载」提供了可能——**即使编译时该类的 `.class` 不存在，运行时才提供也能正常工作**。

### 反射能做什么

拿到 `Class` 对象后，可以做以下事情：

| 能力 | 对应 API | 说明 |
|:---|:---|:---|
| 创建实例 | `clazz.newInstance()` / `getConstructor().newInstance()` | 甚至能调用私有构造器 |
| 获取/设置字段 | `Field.get()` / `Field.set()` | **可访问私有字段** |
| 调用方法 | `Method.invoke()` | **可调用私有方法** |
| 获取类信息 | `getName()`、`getSuperclass()`、`getInterfaces()` | 类的结构信息 |
| 获取注解 | `getAnnotation()`、`isAnnotationPresent()` | 注解处理的基础 |
| 操作数组 | `Array.newInstance()`、`Array.set()` | 动态创建和操作数组 |
| 访问修饰符 | `getModifiers()` | 判断类/成员的访问级别 |

**关键突破**：反射通过 `setAccessible(true)` **可以访问私有成员**，这打破了封装——既是它的强大之处，也是它的风险所在。

## java.lang.reflect

`Class` 类提供了获取类结构信息的入口，而 `java.lang.reflect` 包提供了**具体操作这些成员的类**。

| 类 | 代表什么 | 核心方法 | 用途 |
|:---|:---|:---|:---|
| **`Field`** | 类中的**字段**（成员变量） | `get()`、`set()`、`getType()`、`getName()` | 读取和修改字段值，**可访问私有字段** |
| **`Method`** | 类中的**方法** | `invoke()`、`getReturnType()`、`getParameterTypes()` | 调用方法，**可调用私有方法** |
| **`Constructor`** | 类的**构造器** | `newInstance()`、`getParameterTypes()` | 创建对象实例 |
| **`Modifier`** | **修饰符** | `isPublic()`、`isStatic()`、`isFinal()` | 解析访问修饰符 |
| **`Array`** | **数组** | `newInstance()`、`get()`、`set()`、`getLength()` | 动态创建和操作数组 |
| **`Parameter`** | 方法的**参数** | `getName()`、`getType()`、`getAnnotations()` | 获取参数信息（需 `-parameters` 编译） |
| **`AnnotatedElement`** | **注解**（接口） | `getAnnotation()`、`getAnnotations()` | 读取注解信息 |

### Field：操作字段

```java
Class<?> clazz = User.class;
Object instance = clazz.getDeclaredConstructor().newInstance();

// 获取字段（含私有）
Field field = clazz.getDeclaredField("name");
field.setAccessible(true);        // 突破私有访问限制

field.set(instance, "张三");       // 设置值
Object value = field.get(instance);  // 读取值

// 其他常用方法
field.getType();      // 字段类型 Class
field.getName();      // 字段名
field.getModifiers(); // 修饰符
```

### Method：调用方法

```java
Method method = clazz.getDeclaredMethod("setName", String.class);
method.setAccessible(true);

// invoke(目标对象, 参数列表)
Object result = method.invoke(instance, "张三");

// 静态方法传 null 作为目标对象
Method staticMethod = clazz.getDeclaredMethod("staticFunc");
staticMethod.invoke(null);

// 其他常用方法
method.getReturnType();       // 返回类型
method.getParameterTypes();   // 参数类型数组
method.getParameterCount();   // 参数个数
```

### Constructor：创建实例

```java
// 无参构造
Constructor<?> noArg = clazz.getDeclaredConstructor();
Object obj1 = noArg.newInstance();

// 有参构造
Constructor<?> withArgs = clazz.getDeclaredConstructor(String.class, int.class);
Object obj2 = withArgs.newInstance("张三", 18);

// 私有无参构造也能调用
Constructor<?> privateCtor = clazz.getDeclaredConstructor();
privateCtor.setAccessible(true);
Object obj3 = privateCtor.newInstance();
```

> **注意**：`Class.newInstance()` 在 JDK 9 已废弃，应改用 `clazz.getDeclaredConstructor().newInstance()`。

### getDeclaredXxx() 与 getXxx() 的区别（易混淆点）

这是反射 API 中**最容易搞混**的地方：

| 方法族 | 含义 | 是否包含私有 | 是否包含继承 |
|:---|:---|:---|:---|
| `getDeclaredFields()` | 获取**本类声明的所有字段** | ✅ 包含 | ❌ **不含父类** |
| `getFields()` | 获取**可访问的公有字段** | ❌ 不含私有 | ✅ 含父类 |
| `getDeclaredMethods()` | 获取**本类声明的所有方法** | ✅ 包含 | ❌ **不含父类** |
| `getMethods()` | 获取**可访问的公有方法** | ❌ 不含私有 | ✅ 含父类 |

```java
Class<User> clazz = User.class;

clazz.getDeclaredFields();   // 本类全部字段（含 private），不含继承
clazz.getFields();           // 本类 + 父类的 public 字段

clazz.getDeclaredMethods();  // 本类全部方法（含 private），不含继承
clazz.getMethods();          // 本类 + 父类的 public 方法
```

**记忆技巧**：
- 带 **`Declared`** → 只管「**自己声明的**」，所以包含私有、不含继承。
- **不带 `Declared`** → 只管「**能访问到的**」，所以只有 public、但含继承。

### 访问私有成员的前提

`setAccessible(true)` 是访问私有成员的关键，但它**不是无条件生效**的：

- Java 9 引入**模块系统**后，反射访问其他模块的非公开成员会被拒绝。
- 需要目标模块显式 `opens` 该包，或在启动参数中加 `--add-opens`。
- 对于 JDK 内部 API（如 `sun.misc.Unsafe`），强反射访问会抛 `InaccessibleObjectException`。

```java
field.setAccessible(true);   // 可能抛 InaccessibleObjectException
```

> 这是 Java 9+ 的一个重要变化，很多老代码在升级时因此报错。
## 反射的优缺点
### 优点
#### 可扩展性
应用程序可以利用全限定名创建可扩展对象的实例，来使用来自外部的用户自定义类。
#### 类浏览器和可视化开发环境
一个类浏览器需要可以枚举类的成员。可视化开发环境（如 IDE）可以从利用反射中可用的类型信息中受益，以帮助程序员编写正确的代码。
#### 调试器和测试工具
调试器需要能够检查一个类里的私有成员。测试工具可以利用反射来自动地调用类里定义的可被发现的 API 定义，以确保一组测试中有较高的代码覆盖率。
### 缺点
#### 性能开销
反射涉及了动态类型的解析，所以 JVM 无法对这些代码进行优化。因此，反射操作的效率要比那些
非反射操作低得多。我们应该避免在经常被执行的代码或对性能要求很高的程序中使用反射。
#### 安全限制
使用反射技术要求程序必须在一个没有安全限制的环境中运行。如果一个程序必须在有安全限制的
环境中运行，如 Applet，那么这就是个问题了
#### 内部暴露
由于反射允许代码执行一些在正常情况下不被允许的操作（比如访问私有的属性和方法），所以使
用反射可能会导致意料之外的副作用，这可能导致代码功能失调并破坏可移植性。反射代码破坏了抽象性，因
此当平台发生改变的时候，代码的行为就有可能也随着变化。

## java反射中，Class.forName和classloader的区别
java中class.forName()和classLoader都可用来对类进行加载。

class.forName()前者除了将类的.class文件加载到jvm中之外，还会对类进行解释，执行类中的static块。

而classLoader只干一件事情，就是将.class文件加载到jvm中，不会执行static中的内容,只有在newInstance才会去执行static块。

Class.forName(name, initialize, loader)带参函数也可控制是否加载static块。并且只有调用了newInstance()方法采用调用构造函数，创建类的对象
```java
public static Class<?> forName(String className)
            throws ClassNotFoundException {
    Class<?> caller = Reflection.getCallerClass();
    return forName0(className, true, ClassLoader.getClassLoader(caller), caller);
}
```
```java
public static Class<?> forName(String name, boolean initialize,ClassLoader loader)throws ClassNotFoundException{
    Class<?> caller = null;
    SecurityManager sm = System.getSecurityManager();
    if (sm != null) {
        // Reflective call to get caller class is only needed if a security manager
        // is present.  Avoid the overhead of making this call otherwise.
        caller = Reflection.getCallerClass();
        if (sun.misc.VM.isSystemDomainLoader(loader)) {
            ClassLoader ccl = ClassLoader.getClassLoader(caller);
            if (!sun.misc.VM.isSystemDomainLoader(ccl)) {
                sm.checkPermission(
                    SecurityConstants.GET_CLASSLOADER_PERMISSION);
            }
        }
    }
    return forName0(name, initialize, loader, caller);
}
```
## 反射的使用场景

反射的核心价值是**在运行时才确定要操作的类**，从而实现解耦和通用化。下面按「框架常用 → 日常开发」的顺序，列出主要使用场景。

### 1. 框架的依赖注入（Spring IOC）

Spring 启动时扫描到 `@Component`、`@Service` 等注解的类，通过反射创建实例，再把依赖注入进去。整个过程在运行时完成，框架编译期并不知道用户的业务类。

```java
// 简化版 IOC：通过反射实例化并注入
Class<?> clazz = Class.forName("com.example.service.UserService");
Object instance = clazz.getDeclaredConstructor().newInstance();

// 给 @Autowired 标注的字段注入依赖
for (Field field : clazz.getDeclaredFields()) {
    if (field.isAnnotationPresent(Autowired.class)) {
        Object dependency = container.getBean(field.getType());
        field.setAccessible(true);   // 私有字段也能注入
        field.set(instance, dependency);
    }
}
```

**关键点**：`setAccessible(true)` 突破了私有访问限制，这正是 Spring 能给 private 字段注入的原因。

### 2. 数据库驱动的动态加载（JDBC）

JDBC 是反射最经典的场景。`DriverManager` 拿到的是全限定名字符串，运行时才加载具体驱动实现，所以换数据库只需改配置，不用改代码。

```java
// 方式一：显式加载（会执行 static 代码块，向 DriverManager 注册自己）
Class.forName("com.mysql.cj.jdbc.Driver");

// 方式二：SPI 自动加载（JDBC 4.0+，META-INF/services 声明）
Connection conn = DriverManager.getConnection(url, user, password);
```

```java
// MySQL Driver 静态块的本质：靠反射把自己注册进去
public class Driver extends NonRegisteringDriver implements java.sql.Driver {
    static {
        try {
            java.sql.DriverManager.registerDriver(new Driver());
        } catch (SQLException E) {
            throw new RuntimeException("Can't register driver!");
        }
    }
}
```

### 3. ORM 框架的对象映射（MyBatis / Hibernate）

数据库查出的 `ResultSet` 需要映射成 Java 对象。ORM 框架通过反射读取实体类的字段，再逐个 `set` 值，无需为每张表手写映射代码。

```java
// 模拟 MyBatis 的结果集映射
public static <T> T mapRow(ResultSet rs, Class<T> clazz) throws Exception {
    T obj = clazz.getDeclaredConstructor().newInstance();
    for (Field field : clazz.getDeclaredFields()) {
        field.setAccessible(true);
        Object value = rs.getObject(toUnderline(field.getName())); // userName -> user_name
        field.set(obj, value);
    }
    return obj;
}
```

### 4. 动态代理（AOP 的底层实现）

Spring AOP 的事务、日志、权限等功能，本质上是在目标方法前后织入逻辑。JDK 动态代理就是基于反射 `Method.invoke()` 实现的。

```java
public class LogHandler implements InvocationHandler {
    private final Object target;

    public LogHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("方法执行前：" + method.getName());
        Object result = method.invoke(target, args);   // 反射调用真实方法
        System.out.println("方法执行后：" + method.getName());
        return result;
    }
}

// 生成代理对象
UserService proxy = (UserService) Proxy.newProxyInstance(
        target.getClass().getClassLoader(),
        target.getClass().getInterfaces(),
        new LogHandler(target));
proxy.save();
```

> **补充**：CGLIB 走的是字节码增强，不依赖接口，但方法调用环节同样离不开反射。

### 5. 注解处理与配置解析

注解本身只是「标记」，没有任何行为。真正读取注解值并执行逻辑的，是反射 API。

```java
public class Validator {
    public static void validate(Object obj) throws Exception {
        Class<?> clazz = obj.getClass();
        for (Field field : clazz.getDeclaredFields()) {
            if (field.isAnnotationPresent(NotNull.class)) {
                field.setAccessible(true);
                if (field.get(obj) == null) {
                    throw new IllegalArgumentException(
                            field.getName() + " 不能为空");
                }
            }
        }
    }
}
```

### 6. JSON / 序列化框架

Jackson、Gson、Fastjson 在序列化/反序列化时，都要通过反射遍历对象的 getter/setter 或字段。

```java
// 简化版序列化：反射读取字段拼成 JSON
public static String toJson(Object obj) throws Exception {
    StringBuilder sb = new StringBuilder("{");
    for (Field field : obj.getClass().getDeclaredFields()) {
        field.setAccessible(true);
        sb.append("\"").append(field.getName()).append("\":\"")
          .append(field.get(obj)).append("\",");
    }
    return sb.deleteCharAt(sb.length() - 1).append("}").toString();
}
```

### 7. 通用工具与 Bean 拷贝（BeanUtils）

对象属性拷贝、Map 与 Bean 互转这类通用工具，靠反射实现「不关心具体类型」。

```java
public static void copyProperties(Object source, Object target) throws Exception {
    Map<String, Field> targetFields = new HashMap<>();
    for (Field f : target.getClass().getDeclaredFields()) {
        targetFields.put(f.getName(), f);
    }
    for (Field srcField : source.getClass().getDeclaredFields()) {
        srcField.setAccessible(true);
        Field targetField = targetFields.get(srcField.getName());
        if (targetField != null) {
            targetField.setAccessible(true);
            targetField.set(target, srcField.get(source));
        }
    }
}
```

> **注意**：反射版拷贝性能较差，高频场景（如大批量数据转换）应改用 `MapStruct`、`BeanCopier` 等编译期生成的方案。

### 8. 单元测试框架（JUnit）

JUnit 通过反射发现 `@Test` 标注的方法并调用，同时测试常常需要访问被测类的私有方法或字段。

```java
// JUnit 大致执行流程
for (Method method : testClass.getDeclaredMethods()) {
    if (method.isAnnotationPresent(Test.class)) {
        Object testInstance = testClass.getDeclaredConstructor().newInstance();
        method.invoke(testInstance);   // 反射调用测试方法
    }
}
```

### 9. 插件化与 SPI 机制

SPI（Service Provider Interface）是 Java 官方的插件机制，允许第三方提供实现。`ServiceLoader` 通过反射加载 `META-INF/services` 中声明的实现类。

```java
// 定义接口：com.example.Plugin
ServiceLoader<Plugin> loader = ServiceLoader.load(Plugin.class);
for (Plugin plugin : loader) {
    plugin.execute();   // 运行时发现并调用第三方实现
}
```

**典型应用**：JDBC 驱动、SLF4J 日志实现、Dubbo 扩展点加载。

### 10. IDE 与调试工具

- **IDE 智能提示**：IDEA 遍历项目所有 Class 信息，才能提示类名、方法名和参数。
- **调试器**：需要读取对象的私有字段值，反射是唯一手段。
- **热部署 / 代码检查**：Lombok、AspectJ 等工具都依赖反射和字节码操作。

### 使用场景总结

| 场景 | 反射发挥的作用 | 典型框架/API |
|:---|:---|:---|
| 依赖注入 | 运行时实例化 + 字段注入 | Spring |
| 数据库驱动 | 按全限定名动态加载类 | JDBC |
| ORM 映射 | 遍历字段做 Set/Get | MyBatis、Hibernate |
| 动态代理 | `Method.invoke()` 调用目标方法 | Spring AOP |
| 注解解析 | 读取注解元数据并执行逻辑 | 各注解框架 |
| JSON 序列化 | 遍历字段读写值 | Jackson、Gson |
| Bean 拷贝 | 通用属性复制 | BeanUtils |
| 单元测试 | 发现并调用测试方法 | JUnit |
| SPI 插件 | 运行时加载第三方实现 | ServiceLoader、Dubbo |
| IDE / 调试 | 枚举类成员、读取私有关联成员 | IDEA、JDB |

**选择原则**：
- **框架层**：反射不可避免，是用来实现「通用能力」的基础设施。
- **业务层**：能用接口、多态、反射就应避免直接写反射代码——性能差、编译期无检查、可读性低。
- **性能敏感路径**：若必须用反射，可通过缓存 `Method`/`Field` 对象、`setAccessible(true)` 关闭访问检查，或使用 `MethodHandle`、`LambdaMetafactory` 来优化。
